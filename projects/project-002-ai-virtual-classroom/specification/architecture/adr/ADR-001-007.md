# ADRs 001–007 (instantiated 2026-11-05, as Pass 018 planned)

Accepted decisions are not rewritten; a change gets a new ADR that supersedes the old one.

| ADR | Decision | Status |
|---|---|---|
| 001 | Python + FastAPI research application | Accepted |
| 002 | SQLite before any graph database. The learner store is an append-only event table replayed into the kernels; the course graph is rebuilt deterministically from `course.py`. | Accepted |
| 003 | Deterministic policy code owns every authority and mastery transition; no model output can change them | Accepted |
| 004 | Provider-neutral AI boundary (`roles.generate`); no provider connected yet | Accepted |
| 005 | Plain HTML/CSS/JS served by the app before any React. Not Jinja server rendering: the page reads a small JSON API, as in the other Project OS apps. | Accepted, deviation noted |
| 006 | No blockchain in the research kernel | Accepted |
| 007 | Single user first; no accounts or multi-tenancy | Accepted |

Deviation from Pass 018's suggestion: no SQLAlchemy. The persistence surface is one table, so plain `sqlite3` is simpler; revisit when course authoring is persisted.
