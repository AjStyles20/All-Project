# P001 Competence Claim Model — Development Candidate v1.0

A **Competence Claim** is a bounded statement about a programming ability. These definitions are development candidates pending independent assessor/pilot validation.

- **CC1 — Code Comprehension:** explain important purpose/behaviour of submitted code.
- **CC2 — Execution Tracing:** correctly reason through material program execution states.
- **CC3 — Test Design:** independently design a relevant test, expected result and defensible reason for the test.
- **CC4 — Debugging and Diagnosis:** identify, explain and correct a relevant defect.
- **CC5 — Independent Program Modification:** perform a bounded specification-driven modification while preserving required behaviour.
- **CC6 — Construct/Concept Understanding:** demonstrate understanding of a materially used programming construct.

## Applicability

Each case marks a claim as:
- REQUIRED
- NOT_APPLICABLE

Applicability is not an evidence state.

## Evidence states

- SUPPORTED
- PARTIAL
- UNRESOLVED
- CONTRADICTED

The exact PARTIAL/UNRESOLVED boundary remains a scientific validation item. Current CC3 development code uses an explicit structured rubric solely to make the first vertical slice deterministic and testable.
