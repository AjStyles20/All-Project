# P004 benchmark results (2026-11-05)

Specification: `SPECIFICATION.md` (committed in `ef57e6a` before any code). Policies and cost model frozen in `0970587` before the final run. Raw data: `results/final_summary.json`, `results/cost_model.json`, `results/corpus_manifest.json` (per-object rows are regenerated by `python -m p004.benchmark final`).

Hardware: the development laptop, an Intel Atom/Celeron-class CPU (Family 6 Model 76), Windows 10, Python 3.14. WebP encoding of a 2-megapixel photo takes 2.5–3 s here.

Against the thresholds fixed in §9:
- **Q1 met:** 3 regressions, against at least 147 for B1–B3.
- **Q2 met:** on N1 and N2, B4 kept 99 % and 98 % of B3's bytes saved.
- **Q3 met:** every no-transform, oversized and broken object was passed through byte-for-byte, and all ten security invariants pass their tests.
- **Q4 met:** B4's decisions are a pure function of recorded inputs and the frozen model (tested).
- **Kill check not triggered:** B4 and B3 made the same decision on 42 % of eligible object-profile pairs (threshold 90 %).

B4's three regressions were all cost-model misses: encoding took longer than predicted (two photos on N1/N2, one stylesheet on N4).

## What this does and does not show
1. **Built-in advantage.** B4 predicts with the same completion-time formula the benchmark uses to score. Part of its win is optimising the scoring rule directly. A real network would test the prediction against reality.
2. **Network is modelled, not emulated** (no netem on Windows). Completion time = measured work + one round trip + bytes ÷ bandwidth. No packet loss, TCP slow start or HTTP/2 effects.
3. **Verification cost was not counted.** B4's fidelity check adds 24–56 % on top of encoding time on this laptop (measured afterwards: 710 ms on a 3,111 ms-class photo). In the live gateway, encoding plus checking a 2-megapixel photo exceeded the 5 s limit on the slow profile, so the original was served. That is safe, but no saving. This is Pass 004 Q5: on this low-spec CPU, part of B4's governance overhead eats into the gain.
4. **Time is the only objective.** On fast links B4 sends almost everything unchanged (4.5 % saved). That is right for speed but not for someone paying per megabyte, unless they send `Save-Data`.
5. The corpus is synthetic and the same agent wrote the policies and the benchmark.

## Live check
Origin and gateway were run as real servers on 127.0.0.1 and probed with curl:
- **Correct decisions:** passed through on the fast link; gzip on a slow link (88,805 bytes to 11,693); tiny file left alone; no-transform abstained.
- **Security checks held:** the absolute-form target was refused (400), and the upstream redirect was returned, not followed (302).
- **Bug found and fixed:** the lab gateway first started without its fitted cost model, so B4 never transformed anything. A regression test now covers this.
